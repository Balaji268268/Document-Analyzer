## Development Setup

```bash
# Clone repository
git clone https://github.com/Balaji268268/Document-Analyzer.git
cd Document-Analyzer

# Create virtual environment
python -m venv .venv
source .venv/bin/activate  # Linux/macOS
# or: .venv\Scripts\activate  # Windows

# Install the package (and dev tools) in editable mode.
# Use `.[gui,runtime,dev]` to install local LLM runtime, QML GUI, and development tooling.
pip install -e ".[gui,runtime,dev]"

# Quick smoke tests
python -c "from docsummarizer.document_parser import extract_text; print('Parser OK')"
python -c "from docsummarizer.model_manager import is_model_downloaded; print('Model manager OK')"

# Quality gate (matches CI)
ruff check .
mypy
pytest --cov=docsummarizer
```

Pre-commit hooks mirroring CI are available:

```bash
pip install pre-commit && pre-commit install
```

### Reproducible Installs (Lockfile)

`pyproject.toml` declares loose dependency constraints (e.g. `pypdf>=6.14,<7`). `requirements.lock` pins every transitive dependency to an exact version + hash, generated by `uv pip compile`.

For day-to-day development, `pip install -e ".[gui,runtime,dev]"` is fine — it follows the loose constraints. For reproducible release builds, install from the lockfile first:

```bash
pip install -r requirements.lock          # exact pinned versions, hash-verified
pip install --no-deps -e .                # register the local package
```

To regenerate the lockfile after editing `pyproject.toml`:

```bash
uv pip compile pyproject.toml --generate-hashes -o requirements.lock
```

## Module Documentation

### document_parser.py

Handles text extraction from various document formats and images.

**Functions:**
- `extract_text(file_path) -> tuple[str, str | None]` - Main extraction function returning `(text, error)`
- `extract_from_pdf(file_path) -> str` - PDF text extraction using `pypdf` with Tesseract OCR fallback for scanned pages
- `extract_from_docx(file_path) -> str` - Word document extraction via `python-docx`
- `extract_from_rtf(file_path) -> str` - Rich Text Format extraction via `striprtf`
- `extract_from_txt(file_path) -> str` - Plain text with `chardet` encoding detection
- `extract_from_image(file_path) -> str` - Image OCR extraction using `Pillow` and `pytesseract`
- `get_document_info(file_path) -> DocumentInfo` - File metadata (TypedDict)
- `analyze_document(file_path, text=None) -> DocumentStats` - Rich document header statistics

**Supported Formats:**
- `.pdf` - PDF documents (digital text streams & scanned PDF page OCR fallback)
- `.docx` - Microsoft Word (modern XML format only; legacy `.doc` binary OLE is unsupported)
- `.rtf` - Rich Text Format
- `.txt`, `.md`, `.text` - Plain text (with `chardet`-based encoding detection)
- `.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`, `.tiff` - Image OCR (via `Pillow` & `pytesseract`)

### model_manager.py

Handles local GGUF LLM downloading, map-reduce chunking, and inference.

**Classes & Dataclasses:**
- `ModelConfig` - Frozen dataclass describing a GGUF model on HuggingFace Hub
- `SummaryPoint` - Single summary claim with optional `SourceSpan` citation grounding
- `StructuredSummary` - Immutable structured summary containing `summary_type`, `lead`, `points`, `sections`, `text`, and `suggestions`
- `Summarizer` - Main model manager and inference execution engine

**Functions:**
- `get_models_directory() -> Path` - Get platform model storage path
- `is_model_downloaded() -> bool` - Check if default GGUF model file exists
- `get_model_path() -> Path` - Get full path to the downloaded `.gguf` file
- `download_model(progress_callback) -> tuple[Path, str | None]` - Asynchronous download from HuggingFace

**Summarizer Methods:**
- `__init__(model_path, n_ctx=8192, n_threads=None, n_gpu_layers=0)` - Initialize `Llama` context.
  `n_gpu_layers=0` keeps inference on CPU; `-1` offloads layers to GPU.
- `summarize(text, summary_type, max_tokens, progress_callback)` - Generate a plain-text summary.
- `summarize_structured(text, summary_type, should_cancel, progress_callback) -> StructuredSummary` - Generate a structured summary with grounded citations and document improvement suggestions.

### provenance.py

Computes source sentence alignment and character offset grounding for key points.

**Functions:**
- `split_sentences(text) -> list[tuple[int, int]]` - Character offsets for all sentence bounds in text.
- `locate_quote(quote, text, sentences) -> SourceSpan | None` - Fuzzy sequence matching (`difflib`) to ground quotes in source text.

### ui/bridge.py & PySide6 QML UI

Bridge object (`ConsoleBridge`) connecting Qt/QML view states with asynchronous Python worker threads (`QThreadPool`).

**Key Properties & Signals:**
- `busy` (`bool`) - Indicates active text extraction, model loading, or inference.
- `summaryProgress` (`float`) - Real-time progress percentage (`0.0`–`100.0`).
- `statusText` (`str`) - Live status message displayed in status bar and loader.
- `summaryReady` (`Signal`) - Emits plain dictionary containing `lead`, `points`, `sections`, `suggestions`, and `text` for QML views.

**QML View Components (`src/docsummarizer/ui/qml/App/`):**
- `SummaryScreen.qml` - Main dual-pane view (source abstract pane + distilled summary pane).
- `Skeleton.qml` - Futuristic loader with animated gradient progress bar, spinning hex scanner, and shimmer cards.
- `SegmentedControl.qml` - Mode selector control (**Brief**, **Detailed**, **Structured**).
- `Theme.qml` - Design system design tokens (`Theme.accent`, `Theme.block`, `Theme.serif`, `Theme.mono`).

### cli.py

Command-line interface for terminal usage and automation scripts.

**Usage:**
```bash
docsummarizer-cli <input> [-t TYPE] [-o OUTPUT] [--gpu|--no-gpu] [--threads N] [--download-only]
```

## GPU Acceleration (Optional)

Inference runs on CPU by default. To enable GPU acceleration, install a CUDA/Metal build of `llama-cpp-python` and enable GPU Acceleration in Settings (or pass `--gpu` on CLI).

### NVIDIA GPU (CUDA)

Prebuilt CUDA wheels can be installed without a local CUDA toolkit:

```bash
pip uninstall llama-cpp-python -y
pip install llama-cpp-python \
  --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124
```

To compile from source (requires CUDA Toolkit and MSVC/GCC):

```bash
CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python --no-cache-dir
```

## Adding New Document Formats

To add support for a new document extension:

1. Add an extraction function in `document_parser.py`:
```python
def extract_from_newformat(file_path: str) -> str:
    # Your extraction logic
    return extracted_text
```

2. Register it in `_EXTRACTORS` and `_PARSER_LABELS`:
```python
_EXTRACTORS = {
    ".pdf": extract_from_pdf,
    ".newformat": extract_from_newformat,
}

_PARSER_LABELS = {
    ".pdf": "pypdf",
    ".newformat": "newformat-parser",
}
```

`SUPPORTED_EXTENSION_SET` and dialog filters automatically derive from `_EXTRACTORS`.

## Known Limitations

- **Password-Protected PDFs:** Encrypted PDFs require password decryption before loading.
- **Complex Multi-Column Layouts:** Complex PDF tables or multi-column text streams may require manual verification if standard text stream order is irregular.
